# 样例数据说明

这些文件是用来试内核的样例，不是数据库里的表，也没有 `title` 字段。真正的数据只有两种：`session` 里面的一次辅导，`plan` 里面的一份计划。

## 文件外层

辅导文件外面只有一个 `session`。计划文件外面有两个东西：

- `previousVersion`：手机上当前是第几版。第一版用 `null`。它不属于计划本身，只给检查用。
- `plan`：计划本体。

`data/answers.json` 不是第三种文档。它是一组「孩子怎么答、标准答案是什么、程序应该判 hit 还是 miss」。

`data/pack.json` 也不是文档，更不是课包的正式格式。它是这一轮最小回路要用的四句题目原文，每句只有已经定下的 `recognizedText`。没有 `title`，没有标准答案，没有拆好的问。模型以后只读这句原文。下面这列答案只给测试时对照，不在文件里：

| 原文 | 在看什么 | 对照答案 |
|---|---|---|
| `They ___ my friends. (am / is / are)` | 选词 | `are` |
| `This is an ___. (apple / apples)` | 填空 | `apple` |
| `改错（只改一个词）：She like cats.` | 改一个词 | `likes` |
| `看中文写单词：书 b__k` | 单词拼写 | `book` |

`data/synthetic.json` 也不是文档。它是另写的一批测试数据，不是要存进手机或云端的数据。`answers` 是判题。`traces` 是写好期望记录的讲题过程。`refused` 是必须拒绝讲的拆题。`pools` 和 `patterns` 会组成更多回放。`facts` 是不同的编号、孩子、课包或现拍、断网或有网。每份都会和讲题过程、拒绝的拆题配成一整条辅导。`assemblies` 是另外写死期望的整条记录，用来看旧记录会不会被拿来用、失败时兜底的话会不会被当成答案。

## 四次辅导

| 文件 | 在看什么 |
|---|---|
| `sessions/s01_be_verb.json` | 断网拍的填空 `I ___ a student.`。先答 `is`，再答 `I am`，都算错；最后答 `是am`，算对。检查通过。 |
| `sessions/s02_spelling.json` | 课包里的拼写。`apples` 算错，`Apple` 算对。 |
| `sessions/s03_split_failed.json` | 这一问没有 `expect`。检查失败，原因是 `missing_expect`。不讲题，记录里只有 `note`。 |
| `sessions/s04_answer_leaked.json` | 第二问的答案 `apple` 已经写在第一问的 `ask` 里。检查失败，原因是 `answer_leaked`。这不算孩子答错。 |

同一问的 `ask` 里写出选项是允许的。`s01` 的问句里就有 `am、is 还是 are`，它仍然通过。

## 三份计划

| 文件 | 在看什么 |
|---|---|
| `plans/child01_v1.json` | 还没有辅导记录。`previousVersion` 是 `null`，`planVersion` 是 1，`basedOnSessionId` 是 `null`。 |
| `plans/child01_v2.json` | 看过 `s_01` 之后写成的第 2 版。`reminders` 里是这个孩子的错。`examples` 里只有题目和正确答案，没有他写过的 `is`。 |
| `plans/child01_bad.json` | 不能进手机。版本从 1 跳到 4，`voice` 是空白，提醒 4 句，样例 4 道。 |

## 怎么试

在项目目录运行：

```powershell
python data/check_datasets.py
```

脚本用 `xiangke/kernel.py` 重算每条样例。辅导文件里的 `checkPassed`、`checkReasons`，以及 `hit` / `miss` 记录，必须和程序算出来的一致。检查通过的辅导会按孩子的原话回放，再交一整条辅导，必须和文件一致。检查失败的辅导里，记录只能是 `note`，回放会被拒绝；整条辅导仍保留原来的问，并且只收文件里那条兜底的话。
