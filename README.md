# 乡课英语：断网也能用的小学英语辅导

乡村孩子晚上做英语作业，家里常常没有人能听出 `I am` 和 `I is` 的区别。这个项目让孩子拍下一道题，在**断网**的情况下，由本地小模型一步步带着做，程序负责判对错。

联网之后，云端的星火大模型读这个孩子的记录，更新讲法和档案，给家长和老师写反馈，再发几道专属错题。下次断网时，小模型就按新讲法讲。

> 现在是电脑上的网页程序，用网页代替手机，云端也在同一台电脑上，用页面开关模拟断网。**还不是真手机 App，也还不是真云端服务器。**
>
> 这是 Hack4Good「教育与乡村」赛道的参赛作品。

## 分工：程序给答案，模型来讲

手机上的星火小模型只有 1.7B，会讲错，所以不让它决定对错。

| 环节 | 谁来做 |
|---|---|
| 认题（OCR）、孩子确认题目 | 本地 OCR + 孩子 |
| 算答案 | 程序。算不准就拒绝，不猜 |
| 把题拆成几问、讲解 | **小模型**（最后一问的答案锁成程序算的） |
| 听懂孩子的话（答题、不会、提问、闲聊） | **小模型** |
| 判对错、记录 | 程序 |
| 程序算不出的题 | **小模型试做**，告诉孩子不一定对，不判对错 |

小模型讲的内容要先过程序检查，不合格就换成程序写好的说法。

云端按程序定好的步骤走，每一步的判断交给星火大模型（默认 `spark-x2.6`）：

| 环节 | 谁来做 |
|---|---|
| 档案：做过几次、错过几次 | 程序 |
| 档案：卡在哪、接下来练什么 | **星火大模型** |
| 下一版讲法 | **星火大模型**，程序检查 |
| 错过的原题发回手机 | 程序，答案也由程序算 |
| 新的专属题和答案 | **星火大模型**出题，程序把关，星火看不到答案再做一遍，对不上就不发 |
| 反馈里的次数、要不要老师出手、今晚怎么做 | 程序 |
| 反馈里孩子卡在哪、老师要不要讲 | **星火大模型**，逐句检查，不合格换程序的说法 |

星火写的内容不稳定：我们见过乱码、错答案、语法不通的题，也见过只错一次就下结论的话。所以这些检查不能撤。检查也拦不住所有不好的话，真实效果还要人读。

## 怎么运行

**Windows，Python 3.10 以上**（我们用 3.13.9）。

1. 装依赖：`pip install -r requirements.txt`
2. 准备小模型（约 1.03 GB），二选一：
   - 直接跑 `python -m xiangke.download_model`，支持断点续传，下完自动核对 SHA256
   - 手动从 <https://www.modelscope.cn/models/xiaobang123/xiangke-lora-job-v5/resolve/master/gguf/xiangke-v5-Q4_K_M.gguf> 下载，放到 `models/v5/gguf/xiangke-v5-Q4_K_M.gguf`

   > 模型权重不放进仓库（GitHub 单个文件上限 100 MB），只放下载脚本和校验值。
3. 准备运行模型的 llama.cpp：从 [llama.cpp releases](https://github.com/ggml-org/llama.cpp/releases) 下载 Windows CPU 版预编译包（我们用的是 build 12084），把 `llama-server.exe` 和同目录的 `.dll` 解压到 `tools/llama.cpp/`。
4. 启动：

| 想做什么 | 命令 | 要不要星火令牌 |
|---|---|---|
| 看完整流程（推荐） | `打包\启动演示-回放.bat`，再照 `演示/演示步骤.md` 操作 | 不要。云端内容是提前录好的，页面会标明 |
| 只用手机端 | `python -m xiangke.app`，打开 `http://127.0.0.1:8765` | 不要 |
| 现场调用星火 | `python -m xiangke.cloud`，再 `python -m xiangke.app` | 要 |

现场调用星火要先在讯飞控制台拿令牌，自己设到环境变量 `AI_API_KEY`，**不要写进文件，也不要发给别人**。地址和模型默认是 `https://maas-api.cn-huabei-1.xf-yun.com/v2` 和 `spark-x2.6`，可以用 `AI_BASE_URL`、`AI_MODEL` 改。孩子的题目和原话会发给星火，不带孩子编号和时间。

老师和家长的页面在 `http://127.0.0.1:8766`。云端现在只监听本机，没有登录，**不能直接放到公网上**。

**用起来要注意：**

- 手机端只有装依赖、下模型和调星火时需要联网，做题可以离线。
- 首页右上角是模拟网络的开关。云端也在这台电脑上，真断网断不开，所以用开关。
- 开始一道题要等 5～15 秒，取决于 CPU。
- 可以试「课包里的题」，也可以输入 `She can ___. (swim / swims)`、`改错（只改一个词）：He go to school.`

只跑测试不需要模型，也不调用星火：`python -m unittest discover -s tests -t .`

**想知道程序是不是活的**，跑这一条：

```bash
python -m xiangke.smoke
```

它会起云端和手机端，断网做一道题，通电同步，再去云端看有没有记录和反馈，六步都过了才算通。不需要模型文件，也不需要星火令牌。**它证明的是流程通、数据通、页面打得开，不证明讲解质量**——讲题那一步用的是写死的两问。

**老师要把自己这单元的题给孩子练**，填 `data/课包模板.xlsx`（格式见 `data/课包格式.md`），然后：

```bash
python -m xiangke.pack 我的课包.xlsx -o data/pack.json
python -m xiangke.app
```

读之前逐行检查：表头、空值、题号重复、词性和题型的写法、规则名称有没有被改。**有一处不合格就整份不收**，并说清是哪张表、第几行、错在哪里——半份课包比没有更糟，老师会以为已经生效。程序算不出答案的题（现在是单词拼写）会单独点出来：这些题手机上只讲、不判对错。

## 微调过程

**基座模型：** `XHToken/Spark-X2.5-1.7B`（星火 1.7B），用 LoRA 微调，基座不变。

模型学的任务是：输入一道孩子确认过的题，以及这个孩子的讲法、易错提醒和拆题样例；输出一个 JSON，把题拆成 2～3 问，每问有问句 `ask`、答案 `expect` 和解释 `explain`。

| 项目 | 取值 |
|---|---|
| 方法 | LoRA，`r=16`，`alpha=32`，`dropout=0.05` |
| 目标模块 | `q_k_v_proj`、`out_proj`、`gate_proj`、`up_proj`、`down_proj` |
| 可训练参数 | 15,826,944，占全部参数的 0.92% |
| 优化器 | AdamW，学习率 `2e-4`，余弦衰减 |
| 硬件 | ModelScope PAI-DSW，NVIDIA A10 24GB，显存峰值 12.75 GB |
| 用时（v5） | 99 分钟 |

量化流程（`训练/v6/export_gguf.sh`、`merge_lora.py`）：fp32 合并 LoRA → bf16 safetensors（约 3.4 GB）→ `convert_hf_to_gguf.py --outtype f16` → `llama-quantize Q4_K_M` → 1.03 GB 的 GGUF。

**一轮一轮怎么改的：**

- **v4：只练拆题**，5123 条。能用训练之外的难题考出问题：把 `She`、`We` 说成「我」（「主语是哪一种」这个问法，`I` 有 44 条，`She` 只有 2 条）；`can swims`、`I has`、`don't`、`was` 的改错 0 条；解释里满是「第三人称单数」。
- **v5：针对错误补数据**，从基座重训 6573 条：代词主语平衡 300 条、`can`/`to`/`does` 后用原形 250 条、改错缺口 300 条、拼写中间字母 100 条、听懂孩子的话 500 条，其余是改了术语的旧数据。
- **这才是这个项目最重要的一条经验：模型错了先查数据，不要直接加数据。** 只凭感觉微调，错误来源是看不出来的。
- **v6：练「照着答案讲」**，数据已备好，还没训练。

## 结果

都是用训练数据之外的题，在普通电脑的 CPU 上考量化后的模型。

| 项目 | v4 | v5 |
|---|---|---|
| 60 道验收题（最后答案） | 40 | **60** |
| 其中 `can`、`to`、`does` | 2/12 | **12/12** |
| 其中改错缺口和 `There` | 6/14 | **14/14** |
| 把主语说成「我」（模型自己做） | 4 次 | **0 次** |
| 听懂孩子的话（60 句） | 19 | **57** |
| 程序能给答案的 28 道里，用模型讲的 | 12 | **24** |
| 判对错用的答案出错 | 0 | 0 |
| **外部 40 题** | **39** | **37（退步）** |

程序算答案：用旧数据的标准答案核对，算了 829 道，错 0 道。但这不代表程序不会错：星火出的题里，`(can / cans)` 程序就算错了，已经修好。

**看这些数字时要注意：**

- **60/60 偏乐观**：验收题和新训练数据都是我们自己写的，句式相近。唯一的外部题反而退步了，所以**真实作业上的水平还不知道**。
- **讲解对不对主要靠人读**：程序只能拦下一部分错误。
- **还没有请老师看过讲解，也没有用真实作业和真手机测过。**
- **演示录屏和录好的星火内容是挑过的**：录了几次，选了内容最准的一份，代表较好的情况，不是平均水平。

## 还没做的

真云端服务器（要加登录和身份校验）、读取老师的课包 Excel、打包成真正的手机 App、真手机测试、手写识别。

孩子提问时，手机端暂不交给小模型续讲：先记下疑惑，联网后由云端星火逐条解答再同步回手机。这条链路已接入代码，但端到端效果还没验证。
